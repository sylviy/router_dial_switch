# 做一个 Web 操作动作单元

**产出是一个动作,不是一套测试。** 它只负责"把设备切到某个状态,并且证明真的
切到了"。

给 agent 的技术细节在 `Tools/probing.md`,适配人员不需要看那份。

## 这份文件是**模板**

一个任务一份 SKILL,跟着它的产出目录走:`Devices/<品牌>_<型号>/<任务名>/SKILL.md`,
**各自自足**。做新任务时:

* `Devices/` 里已经有像的任务 → **把那个目录整个拷过来改**,别回到这份模板;
* `Devices/` 还是空的(现在就是) → 从这份模板拷一份进去,填第一部分。

重复是**刻意的**:一个任务改坏了,绝不会带倒别的任务。

agent 不会自己发明。

## 第二部分 · 规矩(不要改)

这几条是这个工具存在的理由。全部是真机上踩出来的,不是理论。

1. **点完不算数,刷新之后读回来才算数。**
   不刷新,你读到的是自己刚填进去的值,等于自己给自己打分。
   真机上出过:回读通过、实际提交的是旧值。
   工具里对应的是 `act.py --reload-verify`,以及产出脚本里刷新后那次回读。
   **这一步由 agent 自己做,不需要人来确认。**

2. **回读要一模一样,不能"差不多"。**
   目标是 PPPoE,页面显示 PPPoEv6,这不叫成功。差一个字就是失败。
   判定只有一个出口:`Vendor/common/contract.py` 的 `verify()`。

3. **页面上只有一个,不代表它就是对的。**
   真机上出过:同一页 4 个一模一样的保存按钮、8 个藏起来的提交按钮、
   一个人眼永远看不见但点得动的勾选框。所以每个选择器都要
   `probe_count.py` 数过恰好 1,并在 `facts.yaml` 里写明怎么认出它的。

4. **可以直接操作设备,包括保存。**
   适配时台架是断网的,WAN 口也不接出口 —— 点错了不会把人关在门外。
   所以不用停下来等人点头,`--commit` 该给就给。

5. **和任务表对不上时,报告回来,不要自己猜。**
   任务表是人写的,人写错的可能性远大于设备不一样。绕路找补是最贵的做法。

6. **`_pause` / `_find` / `_find_text` 这三个函数不许改。**
   它们在 `Tools/_probe.py` 里,全仓库唯一一份。探针可以整个复制到
   `Devices/<…>/tools/` 下自由编辑 —— 加控件形态、改输出都行 ——
   但这三个原样保留。它们是"工具说命中 1"能预测"脚本也命中 1"的唯一依据。

## 第三部分 · 按需询问(不是关卡)

**默认自己往下走。** 流程表已经把该说的说清楚了,每一步都有「做完的样子」
可以自己验证,不必逐步等人点头。

只有下面这三种情况停下来问 —— 因为它们**再探测也解决不了**:

* 同名控件有好几个而且都可见,任务表里没有能区分它们的话;
* 真机和任务表对不上(那一项根本不存在、或者选项文字不一样);
* 一个动作可能顺带改到任务表没提的别的设置。

问的时候**用设备的话问,不要用选择器语言问**。照这个形状:

> 在「Advanced → VPN Server」页,我认的是:
> Enable = "Enable" 标签右边那个复选框(现在没勾);
> 保存 = 这个表单右下角的 "Save"(同一页还有一个藏起来的同名按钮,我不点它)。
> 同一页另外还有 2 个同样写着 "Save" 的按钮,任务表没说是哪个。
> **请确认:保存是不是右下角这一个?**

## 第四部分 · 产出是什么

一个目录,两个文件:

```
Scene/web_action/Devices/Mercusys_MR80X/vpn_server_switch/
    action.py      这个动作本身,可以单独跑
    facts.yaml     上面那张任务表 + 找到的控件位置(带注释说明怎么确认的)
```

`action.py` 跑起来可以在各个状态之间切换:

```
python action.py pptp_server --ip 192.168.1.1 --pass admin123 --commit
```

命令行、stdout 的 JSON、退出码 0/2/3 的完整契约在 `Tools/probing.md`
的「产出契约」一节。

## 第五部分 · 做完之后必须做的一件事

**把设备恢复到默认状态,再让脚本从头跑一遍。**

第一次跑通的时候,设备往往已经被你手工点到目标状态附近了。这时候的"成功"
可能是假的 —— 脚本其实什么都没做对,只是状态本来就对。

从干净状态跑通,是唯一能区分这两者的办法。跑不过就是还没做完。
