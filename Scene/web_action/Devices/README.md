# Devices/ —— UI 动作单元的交付物放这里

一台设备的一个任务 = 一个目录,**自足**:

```
Devices/<品牌>_<型号>/<任务名>/
    SKILL.md       这个任务的全部:填好的任务表 + 流程 + 规矩
    action.py      这个动作本身,可以单独跑
    facts.yaml     任务表 + 找到的控件位置(带注释说明怎么确认的)
    tools/         可选:从 Tools/ 复制过来、按这台机改过的探针
```

**做新任务 = 把最像的那个目录整个拷过来改。** 这里还是空的时候,从空白模版
`../../../Tools/SKILL_TEMPLATE.md` 拷;想看一份**填好的**长什么样,
`Scene/router_dial_switch/Models/*/SKILL.md` 是同一个骨架的另一批实例。和型号脚本一个取舍:重复换来的是"改第八个任务
绝不可能弄坏前七个"。

现在是空的 —— **样板等真机**。手上没有能访问的设备时,照着抄一份"看起来
对"的脚本,只会让下一个人以为它验过。真机上跑通了再往这里放。

怎么做一个:拷一份 SKILL.md 过来填第一部分(骨架和填法它自己里面写着),
技术细则和产出契约看 `../../../Tools/probing.md`。

工具本身有没有坏,不用等真机 —— `python tests/mock_test.py` 拿假设备页
跑一遍就知道。
