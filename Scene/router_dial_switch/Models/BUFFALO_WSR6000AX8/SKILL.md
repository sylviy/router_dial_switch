## 第二部分 · 规矩(不要改)

这几条是这套东西存在的理由。全部是真机上踩出来的,不是理论。

1. **点完不算数,刷新之后读回来才算数。**
   不刷新,你读到的是自己刚填进去的值,等于自己给自己打分。
   真机上出过:回读通过、实际提交的是旧值。
   **这一步 agent 自己做,不需要人来确认。**

2. **回读要一模一样,不能"差不多"。**
   目标是 PPPoE,页面显示 PPPoEv6,这不叫成功。差一个字就是失败。
   判定只有一个出口:`Vendor/common/contract.py` 的 `verify()`。

3. **页面上只有一个,不代表它就是对的。**
   真机上出过:同一页 4 个一模一样的保存按钮、8 个藏起来的提交按钮、
   一个人眼永远看不见但点得动的勾选框。所以每个选择器都要数过恰好 1,
   并在产出里写明是怎么认出它的。

4. **可以直接操作设备,包括保存。**
   适配时台架是断网的,WAN 口也不接出口 —— 点错了不会把人关在门外。
   所以不用停下来等人点头。

5. **和任务表对不上时,报告回来,不要自己猜。**
   任务表是人写的,人写错的可能性远大于设备不一样。绕路找补是最贵的做法。

6. **不猜没观察过的东西。** 每个选择器都得是探出来的,不是想出来的。

7. **`_pause` / `_find` / `_find_text` 这三个函数不许改。**
   它们在 `Tools/_probe.py` 里,全仓库唯一一份。探针可以整个复制到本目录的
   `tools/` 下自由编辑 —— 加控件形态、改输出都行 —— 但这三个原样保留。
   它们是"工具说命中 1"能预测"脚本也命中 1"的唯一依据。

## 第三部分 · 手上有哪些工具,怎么用它们推进

工具都在仓库根的 `Tools/` 下,**不要自己另写探测脚本**。
下面说的是每个工具**替你做什么**;命令行参数和边界情况在 `Tools/probing.md`。

| 工具 | 它替你做什么 | 什么算过 |
|---|---|---|
| `env_check.py` | 开工前的三项体检:解释器对不对、浏览器起不起得来、设备地址通不通 | 三项全绿。不绿是**环境问题,不是适配问题** —— 如实报告,别去改脚本 |
| `probe_dump.py` | **把当前这一页上能点的东西全抄下来**:每行一个控件,写着它是什么类型(下拉/单选/输入框/按钮)、上面显示什么字、有哪些能指认它的属性、在哪个文档里。回答"这一页到底有什么" | 清单里能对上任务表说的那个控件 |
| `list_modes.py` | 把一个下拉或单选组的**所有选项照原文抄出来**。回答"这个下拉里有哪几档、每一档界面上写的到底是什么字" | 选项数 ≥ 2,而且任务表里的措辞逐字来自这里 |
| `probe_count.py` | 数一个选择器**命中几个**。回答"我说的这个东西,页面上是不是只有一个" | **恰好 1**。多了说明这个说法还不够准 |
| `act.py` | **做一个动作,再回读证明它成了**:选中 / 勾上 / 填进去 / 点下去,然后把控件现在的值读回来,和目标逐字比对 | 回读 == 目标 |
| `tools/make_facts.py` | 把**已经验过的东西**排版成型号脚本(顺带照最像的那台把这份 SKILL.md 也拷一份过去)。它不探测、不猜 | 打出来的骨架里没有 TODO |
| `tools/check_model.py` | 交付物的**离线体检**:不碰设备,只看这个文件自洽不自洽 | 没有 error。**过了 ≠ 验收** —— 真机上还得逐档跑一遍 |

`act.py` 上有三个开关值得单说,它们直接对应任务表里的三样东西:

* `--expect-after "<那个东西>"` ←→ 任务表的「**做完的样子**」。
  做完之后它要出现,这一步才算成立。**用它代替固定等待** —— 页面是逐步展开
  的,等多久没人说得准,但"那个东西出现了"是看得见的。
* `--reload-verify` ←→ 任务表的「**刷新后回读**」。
  刷新页面、重新登录、重走一遍菜单,再读一次。这是判"真的保存住了"还是
  "只是自己刚填的值还留在框里"的唯一办法。
* `--apply-sel "<保存键>"` ←→ 任务表的「**收尾**」。给了就真点保存。

`probe_dump.py` 的清单**只收表单元素**。页面上有、清单里没有,是常事 ——
真机上大量控件不是表单元素(比如图标做的开关,真值藏在旁边的隐藏输入框里)。
遇到就去看 `Tools/probing.md` 的「找不到怎么办」第 2 招,别以为页面上没有。

### 照任务表推进的顺序

```
先跑一次 env_check.py,三项全绿再开工。

对任务表里的每一步:
  1. probe_dump.py  —— 看看现在这一页有什么
  2. 认出任务表说的那个控件,probe_count.py 数一下,必须恰好 1
  3. 是选择类的,list_modes.py 把选项原文抄下来,和任务表里的措辞对一遍
  4. act.py 做这个动作,--expect-after 确认「做完的样子」出现了
  5. 「做完的样子」不成立就**别往下走** —— 页面还没到那个状态,后面全是白找

每个状态都过完之后,最后一遍加上 --apply-sel 和 --reload-verify:
真保存 + 刷新后回读。这一遍过了,才谈得上把它落成脚本。
```

前面 1~4 步**不会改设备**(只读 + 选中,不点保存)。第 5 步起才真下发,
**从最安全的那个状态开始**。

卡在具体现象上(登录不进去、认错控件、选择器收不窄、试切不过),
按节查 `reference.md`,**按节读,别整篇读**。

## 第四部分 · 按需询问(不是关卡)

**默认自己往下走。** 每一步都有能自己验证的通过条件,不必逐步等人点头。

只有下面这三种情况停下来问 —— 因为它们**再探测也解决不了**:

* 同名控件有好几个而且都可见,任务表里没有能区分它们的话;
* 真机和任务表对不上(那一项根本不存在、或者选项文字不一样);
* 一个动作可能顺带改到任务表没提的别的设置。

问的时候**用设备的话问,不要用选择器语言问**。照这个形状:

> 我在「网络 → WAN」页上看到一个下拉,现在显示 "DHCP Client",展开有 5 项:
> Static IP / DHCP Client / PPPoE / PPTP / L2TP。同一页另外还有 2 个长得像
> 的下拉(一个在 MTU 旁边,一个在 DNS 旁边),任务表没说是哪个。
> **请确认:拨号方式是不是这一个?**

## 第五部分 · 产出是什么,怎么跑这一台

产出是**一个目录**,自足 —— 整个拷走就能跑:

```
Models/BUFFALO_WSR6000AX8/
    BUFFALO_WSR6000AX8.py    ← 交付物本体。FACTS(这台机验过的全部事实)+ 切换动作
    SKILL.md              ← 就是本文件
    tools/                ← 可选:从 Tools/ 复制来、按这台机改过的探针
```

在场景目录下跑(`cd Scene/router_dial_switch`):

```
python Models/BUFFALO_WSR6000AX8/BUFFALO_WSR6000AX8.py dynamic            # 只切,看回读,不下发
python Models/BUFFALO_WSR6000AX8/BUFFALO_WSR6000AX8.py dynamic --apply    # 真下发
python Models/BUFFALO_WSR6000AX8/BUFFALO_WSR6000AX8.py dynamic --perf     # 整轮:逐档切 + 测吞吐 + 出报告
python tools/check_model.py BUFFALO_WSR6000AX8       # 离线体检(过了 ≠ 验收)
python app/start.py                  # 或者走向导,不用记命令
```

这台机支持的档:**dynamic / pppoe / transix / v6plus / ocnvc / v6connect**。
这轮测哪几档由 `config.yaml` 的 `run.dial_modes` 决定;
**换被测机只改两处**:`router.ip` 和 `run.dial_modes`。

## 第六部分 · 做完之后必须做的一件事

**把设备恢复到默认状态,再让脚本从头跑一遍。**

第一次跑通的时候,设备往往已经被你手工点到目标状态附近了。这时候的"成功"
可能是假的 —— 脚本其实什么都没做对,只是状态本来就对。

从干净状态跑通,是唯一能区分这两者的办法。跑不过就是还没做完。
