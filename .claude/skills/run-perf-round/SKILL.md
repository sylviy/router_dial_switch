# 跑一整轮 WAN 性能矩阵

## 怎么起

**双击 `start.bat`**(或 `python app/start.py`)→ 选型号 → 选操作。菜单按危险
程度排:

```
1. 只切一档,只看回读不下发   ← 最安全,上台架第一步该做这个
2. 只切一档,并真正下发       ← 会改路由器,要输 yes 确认
3. 整轮性能测试               ← 逐档切换 → 等 WAN → 测吞吐 → 出报告(必定下发)
4. 离线自检                   ← 拿假路由器页面跑一遍,不碰真机
5. 看看 config.yaml 还差什么   ← 带行号
```

命令行等价物:`python models/<型号>.py <档>` / `--apply` / `--perf`。

## 配置只有一处

`config.yaml`,现场用记事本改。**换被测机只改两处**:`router.ip`,和
`run.dial_modes`(这轮测哪几档)。`bench` 段是台架接线,按**拨号方式**走的
—— pppoe 拨通后的对端就是那个隧道网段,换哪台路由器都一样,所以配一次七台
机共用。每一项该填什么见 `docs/config.example.yaml` 的中文注释。

**别自己猜缺什么** —— 跑菜单 5,它会把缺的项连行号一起列出来,而且分两段:
先是"切档要用的",再是"整轮测吞吐才要的"。

## 排查

**全部排查内容在 `skill/reference.md` 的 `§ 整轮跑不起来 / 报告里有 err`
那一节。** 现在去读那一节,别整篇读,也别读 `docs/GOTCHAS.md`(那是给人看的)。

一句话版本:开跑前的报错都会指出**改哪个文件的第几行**,照着改就行;
跑起来之后某一格 `err` 是测量层的错,报告里那格的文字就是原因。

## 这一轮到底在做什么

```
对每个拨号方式:
    型号脚本切到该档并真正下发 → 回读确认 → 等 WAN 拨通 → 稳定
    对 每个频段 × 每种协议 × 每个方向:测吞吐
出 HTML + CSV 报告
```

时序(稳定多久、测多久、等多久)只有一份,在 `config.yaml` 的 `perf` 段,
型号脚本覆盖不了 —— 否则两台机的报告放在一起没有意义。

切换失败的档**不测吞吐**,那一格记 error 继续下一档:一台机坏一档不该拖垮
整轮。
